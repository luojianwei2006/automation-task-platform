## TL;DR

抖音自动化流程已跑通。核心难题：**搜索用户 → 点击第一个视频**。原因是抖音账号主页的视频列表嵌套深，RecyclerView 直接子节点不可点击，视频卡片 `isClickable=false`。最终通过 dump 无障碍树 → 定位 `dsc=[视频，按钮]` → 手势触摸坐标解决。

## 关键修复记录

### 1. clickFirstVideo — 视频节点找不到（3次迭代）

| 版本 | 问题 | 修复 |
|------|------|------|
| v1 | `findFirstClickableInList` 只查 RecyclerView 直接子节点 | → 增强：深度递归 + ViewPager2 匹配 |
| v2 | 深度递归误点头像/关注按钮 | → 回退，只保留 dump 诊断 |
| v3 | dump 发现视频节点 `isClickable=false` | → 匹配 desc 含"视频" + `dispatchGesture` 手势触摸 |

**最终方案**：`findFirstVideoInList` 在 RecyclerView 子树中递归匹配 desc 含"视频"的节点，用 `dispatchGesture` 点击其屏幕坐标中心。

参考 dump 结构：
```
RecyclerView
  LinearLayout          ← 不可点击
    ViewGroup dsc=[视频，按钮]  ← isClickable=false，但手势可触摸
    ViewGroup dsc=[视频，按钮]  ← 第二个
```

### 2. 坐标兼容性增强

- `tapSendNearInput`：`+40` 原始像素 → `+40 * density`（dp 自适应）
- `tapBottomRight`：单点 `(93%, 82%)` → 4 候选位网格扫描

### 3. 去掉自动提交审核

原流程：截图 → `uploadAndSubmit` 自动提交 → 对齐为：截图 → 回传 UPLOAD 标记 → 用户手动提交。

## 经验教训

1. **无障碍树是关键**：dump 页面节点是定位问题最快的方式，不要猜测节点结构。
2. **isClickable 陷阱**：很多 ViewGroup 不标记 clickable，但不等于不能触摸。`dispatchGesture` 比 `ACTION_CLICK` 更可靠。
3. **坐标兜底要谨慎**：深度递归全树搜索容易误点（头像、关注按钮），限定搜索范围（RecyclerView 子树内）更安全。
4. **延迟要够**：抖音视频列表加载可能 3-5 秒，`randomDelay` 给足。

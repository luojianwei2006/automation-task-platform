# 视频剪辑功能增强优化方案

**作者**：许清楚（Xu）· 产品经理  |  **定位**：易用、实用——模板 + 轻量可调，对标抖音/剪映而非专业剪辑面板
**日期**：2026-07-13

---

## A. 现状 vs 差距

| 能力维度 | 已有能力（后端 FFmpeg / MergePreviewService） | 缺失的剪辑能力 |
|---|---|---|
| 拼接 | 多段顺序拼接（concat） | 单段**裁剪/分割**（trim/split） |
| 转场 | xfade 多种 transition | 缺"默认模板套用" + 部分常用类型 |
| 画面基础 | 视频渐入渐出（fade） | **旋转/镜像**、**调速(0.5x~2x)**、**画幅/比例**(9:16/1:1/16:9) |
| 调色 | 无 | **滤镜/调色**（亮度/对比度/饱和度/预设） |
| 字幕 | 单行静态 drawtext | **逐段定时**、**字号/位置/颜色可调** |
| 叠加 | 无 | **贴纸/图片叠加（PiP 画中画）** |
| 音频 | 原声 + 1 条 BGM 循环混音（amix） | **原声音量调节、多 BGM、配音轨、音频淡入淡出** |
| AI/模板 | 无 | **一键成片/模板**、**自动字幕（ASR）** |
| 用户侧编辑 | 安卓端仅能选素材，不能编辑 | 全端缺"轻量可调"编辑入口 |

---

## B. 架构决策：主推「后端服务端编辑」路线

**推荐方案**：定义一套 JSON 化的"编辑时间线/编辑指令"结构，前端/安卓只负责**采集指令与预览**，后端复用现有 FFmpeg 渲染引擎**统一渲染**，沿用"提交 → 异步轮询 → 拿结果 URL"模式。

**为什么比"安卓端本地 ffmpeg"更契合本平台**：
1. **一致性**：一份渲染引擎，两端结果零差异，避免安卓机型碎片化导致的画质/效果偏差。
2. **省电/轻量**：手机本地 ffmpeg 耗电、发热、卡顿；用户端只配置指令+看预览，重活交给服务端。
3. **可云端批量**：契合"自动化任务平台"定位，渲染可队列化、批量、定时，支撑批量发布。
4. **一脉相承**：现有 `MergePreviewController` + `PublishMergeHistory` 已是异步渲染范式，本次只是把"拼接指令"升级为"完整编辑时间线指令"，渲染层可平滑扩展。

**安卓端应保留的轻量交互**（不渲染，只交互）：素材选择、模板/预设选择、参数微调（滑块）、预览播放、一键发布。

```
flowchart LR
    A[管理后台 Vue3] -->|编辑指令 JSON| C{后端渲染引擎}
    B[安卓端 Compose] -->|编辑指令 JSON| C
    C -->|解析为 FFmpeg filter 链| D[(FFmpeg 渲染)]
    D -->|异步| E[PublishMergeHistory 结果URL]
    E -->|轮询| A
    E -->|预览/发布| B
```

## C. 功能清单与优先级

| 优先级 | 功能 | 用户价值（一句话） |
|---|---|---|
| **P0** | 裁剪/分割 | 去掉废片，只保留精华段落 |
| **P0** | 旋转/镜像 | 一键修正横竖屏方向，适配自拍/竖屏 |
| **P0** | 调速（0.5x~2x） | 快动作卡点 / 慢动作更有氛围 |
| **P0** | 画幅/比例（9:16/1:1/16:9） | 一次编辑，多平台自适应发布 |
| **P0** | 转场扩展 + 默认模板 | 不费脑也有顺滑过渡 |
| **P1** | 滤镜/调色（亮度/对比度/饱和度/预设） | 一键美颜调色，风格统一更上镜 |
| **P1** | 字幕增强（逐段定时/字号/位置/颜色） | 无声也能看懂，信息传达更清晰 |
| **P1** | 贴纸/图片叠加（PiP） | 加水印/logo/表情，品牌感与趣味性 |
| **P1** | 音频增强（原声音量/多BGM/配音/淡入淡出） | 背景音乐不抢戏，混音更专业 |
| **P2** | 一键成片/模板 | 选素材+选模板=成片，零门槛出片 |
| **P2** | 自动字幕（ASR 语音转文字） | 省去手打，对标抖音自动字幕（依赖外部 ASR） |

## D. 编辑指令数据结构（指令驱动渲染）

> 设计原则：前端/安卓只产出"时间线指令"，后端渲染引擎解析为 FFmpeg filter 链，与现有异步模式无缝衔接。

```json
{
  "timeline": {
    "output": { "ratio": "9:16", "resolution": "1080x1920", "fps": 30 },
    "audio": {
      "masterVolume": 1.0,
      "bgm": [
        { "trackId": "bgm_01", "src": "music/xxx.mp3", "volume": 0.3, "loop": true, "fadeIn": 2.0, "fadeOut": 2.0 }
      ],
      "voiceover": [
        { "trackId": "vo_01", "src": "voice/xxx.m4a", "volume": 1.0, "start": 5.0 }

      "items": [ { "between": ["seg_01", "seg_02"], "type": "slideleft", "duration": 0.5 } ]
    },
    "segments": [
      {
        "id": "seg_01",

  }
```

## E. 交互设计建议（易用性）

**管理后台（Vue3 · 时间轴 + 片段卡片）**
- 顶部栏：画幅选择、模板选择、预览/导出按钮。
- 中部：横向**时间轴**，每个素材是一张**片段卡片**（缩略图 + 时长 + 拖拽排序）。
- 底部：选中片段 → 弹出**轻量参数面板**（滑块调速度/音量/滤镜强度，开关旋转/镜像）。
- 字幕：点片段 → "加字幕" → 时间轴出现**字幕条**，可拖拽起止、改文字。
- 原则：**所见即所得，少即是多**，默认参数即好看。

**安卓端（Compose · 三步法降门槛）**
1. **选素材**：从素材库勾选视频/图片（已具备）。
2. **选模板**：选风格模板（如"卡点/Vlog/美食"），自动套用转场+滤镜+字幕样式。
3. **微调**：滑块微调速度/音量/滤镜强度，可选手动加字幕。
4. **预览→发布**：点预览 → 服务端渲染低码率草稿返回播放；满意即发布。
- 原则：用户只做**"选择题"**，复杂参数由模板兜底。

## F. 分阶段路线图

| 期次 | 主题 | 可执行项（2-4 个） |
|---|---|---|
| **一期 P0** | 基础剪辑 | ① 定义并落地"编辑时间线 JSON 指令"+ 后端渲染引擎（trim/rotate/speed/ratio）；② 扩展 MergePreviewService 支持单段裁剪/旋转/调速/画幅；③ 转场补 3-5 种 + 默认模板；④ 后台"时间轴+片段卡片"基础 UI 与预览 |
| **二期 P1** | 美化与音频 | ① 滤镜/调色（亮度/对比度/饱和度 + 6-8 预设）；② 字幕增强（逐段定时/字号/位置/颜色）；③ 贴纸/图片叠加 PiP；④ 音频增强（原声音量/多BGM/配音/淡入淡出） |
| **三期 P2** | AI / 模板 | ① 一键成片/风格模板（套用即出片）；② 自动字幕（接入 ASR）；③ 安卓端"三步法"完整交互上线；④ 模板/自定义预设沉淀（可选） |

## G. 待确认问题

1. **安卓预览实时性**：接受"服务端渲染低码率草稿"预览（数秒延迟），还是要本地实时预览（仅解码不渲染）？影响安卓工作量与体验。
2. **自动字幕 ASR**：是否接入付费 ASR、成本由谁承担？P2 是否先不做？
3. **滤镜预设范围**：首期要多少个预设滤镜（建议 6-8 个），有无品牌风格要求？
4. **配音轨来源**：配音仅支持上传音频文件，还是支持手机录音上传？
5. **渲染资源**：服务端批量渲染算力/队列是否充足，是否需对免费用户限流？

---

**方案核心**：以"服务端指令驱动渲染"为底座、用"模板 + 轻量可调"的交互范式，让用户零门槛产出接近剪映质感的短视频，而非面对专业剪辑面板。
